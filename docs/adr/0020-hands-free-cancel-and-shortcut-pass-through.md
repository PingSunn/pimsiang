# Hands-free starts on the second tap's release; Esc and shortcuts are read from a listen-only tap

Hands-free starts when the second tap of a double-tap is released, provided the second press comes within 400 ms of the first release, and the next release of the Trigger key ends it unless another key was pressed while it was down, in which case the press was a shortcut and Hands-free keeps running. If the second press is held past the hold threshold it is Push-to-talk as before, so a tap followed by a hold never opens the microphone twice. The event tap (ADR 0013) now also receives key-down events: Esc cancels the current Utterance (during the hold threshold, Push-to-talk, Hands-free or transcribing), and any other key pressed while the Trigger key is down marks the press as part of a shortcut, which drops it before the microphone opens and cancels an Utterance already started by a slow hold. Esc and the shortcut key still reach the focused app because the tap stays listen-only, so Esc also acts on whatever app is in front.

While the previous Utterance is transcribing, Trigger key events are discarded rather than queued, so a tap made during the transcription is ignored and a new Utterance cannot start until the Final text is delivered. A press that is still held (no release, no other key) when the transcription ends enters the hold threshold at that moment, so it becomes Push-to-talk if it is held on, and it keeps the Shift flag of its press (ADR 0029). Only Trigger key events and audio are discarded: Preferences, Microphone choices, paste-again requests, notices and the microphone-lost signal that arrived meanwhile are handled in order once the Final text is delivered. If Input Monitoring is revoked while an Utterance is pending, listening or loading, the Utterance is cancelled, the microphone stops and the Pill shows the missing permission; the macOS tap also emits a synthetic release when it stops with the Trigger key down. If the microphone cannot be opened after the Start sound, the Stop sound is played too; the Start sound still comes first so it is not recorded. Start and stop sounds are the system sounds Tink and Pop played through the platform trait; they are switched by a controller setting.

## Considered options

- **Start Hands-free on the second press:** a few tens of milliseconds sooner, but a tap followed by a hold would be ambiguous and the microphone would open for what the user means as Push-to-talk.
- **Active tap to swallow Esc while an Utterance is running:** stops Esc reaching other apps, but contradicts ADR 0013 and a slow callback would stall system-wide input.
- **Queue Trigger key presses during transcription:** nothing is lost, but a stale tap would open the microphone after the text is pasted, which the spec forbids. Only a key still physically held at the end is acted on.
