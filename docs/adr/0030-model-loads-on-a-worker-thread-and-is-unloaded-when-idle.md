# The Model loads on a worker thread, audio is buffered meanwhile, and an idle Model is unloaded after ten minutes

Loading the Model takes seconds, and the Utterance controller thread also receives the audio and the Trigger key events, so loading on that thread would let both pile up behind it. The controller now holds the Engine in an `Arc<Mutex<_>>`. When an Utterance starts while the Model is unloaded, it starts the microphone at once, shows the loading state in the Pill, and loads the Model on a short-lived worker thread that sends `Input::ModelLoaded` back to the controller when it is done. The controller never touches the Engine while that load runs: audio is appended to a buffer, release (or the second Trigger press of a hands-free Utterance) only stops the microphone and remembers that the Utterance has ended, and Esc or the Combined key cancels it. When the load finishes, the controller starts the Utterance, pushes the buffered audio and then carries on listening, or, if the key was already released, decodes the buffered audio and delivers the Final text the usual way. A load that fails stops the microphone and shows the "Model not loaded" Pill error. A load that was cancelled still leaves the Model loaded, and an Utterance started meanwhile waits for the same load instead of starting a second one. If the key is pressed again while a Push-to-talk Utterance that was already released is still waiting for the load, and is still held when the load ends, it enters the hold threshold once the Final text is delivered, as in ADR 0020; a press that is released again in the meantime is a tap and is dropped. Loading at startup and after a download uses the same worker thread, so the Trigger key is never queued behind it and a press meanwhile behaves like any other press during a load. A Trigger key combined with another key after the release of an Utterance that is waiting for the load leaves it running instead of cancelling it, and a microphone that stops during the load still shows the microphone-lost notice once the text is delivered.

The controller unloads the Model when the `unload_when_idle` setting is on (the default, `on` or `off` in the settings file) and ten minutes pass with no Utterance. The clock starts when the Model is loaded, restarts after every Utterance that ends or is cancelled, and restarts when the setting is switched on; it is measured with the times the controller already receives in Trigger events and Ticks, so tests drive it with a fake clock. Nothing is unloaded while an Utterance is pending, being listened to, loading or transcribing, and the run loop wakes up for the unload deadline only while there is one. The ten minutes are a constant, not a setting.

On quit the controller finishes the transcription in flight (waiting at most three seconds), the History is flushed, and a pending clipboard restore (ADR 0027) is performed at once instead of being lost. A `--model-dir` whose files are missing is reported as a Model problem in Setup, with a retry that re-checks the folder, instead of a generic Pill error at the first Utterance.

## Considered options

- **Load on the controller thread:** simplest, but key events and audio queue up for the whole load, and the Pill cannot show a loading state until it ends.
- **Make `Engine::load` asynchronous:** pushes threading into every Engine and the fake; the mutex keeps the Engine trait unchanged.
- **Refuse the Utterance until the Model is loaded:** loses the first words after a long break, which is the case this ticket exists to make painless.
- **A user-set idle time:** more settings for little gain; ten minutes is the spec's number.
